# Polylove admin MCP — implementation status

The revised workflow is a private MCP used by the administrator in ChatGPT, not manual copy/paste and not a public member chatbot. GPT reads market/news data and submits a draft; the web administrator still reviews and publishes it. Daily context is not model training.

Implemented: stateless Streamable HTTP `/mcp` using the official MCP SDK; three tools `get_market_snapshot`, `get_market_news`, `submit_analysis_draft`. Snapshots contain server-owned 1h metrics and source references, expire for import after one hour, and are owned by the requesting administrator. Narrative submission cannot override numerical fields. Draft submission is idempotent by snapshot ID, records an initial version and audit actor, and does not publish. Live market ingestion preserves observed entry-crossing evidence for pending snapshots. No tool invokes an AI provider.

OAuth now supports a pre-registered public client configured by `MCP_OAUTH_CLIENT_ID` and an exact HTTPS `MCP_OAUTH_REDIRECT_URI`. Discovery metadata, explicit admin consent, S256 PKCE, single-use hashed codes, resource-bound one-hour opaque tokens and revocation are implemented. Tokens reference the consenting login session: deleting or expiring that session removes access. Client requests must include `resource=<APP_ORIGIN>/mcp` and `scope=market:read analysis:draft`. No refresh token or dynamic client registration is implemented; reauthorize after expiration. This is not yet a claim of ChatGPT compatibility. For now, sign in as admin before starting authorization; automatic return-to-consent after login remains to build.

The earlier development bearer path using `MCP_ADMIN_USER_ID` and `MCP_ADMIN_TOKEN_SHA256` remains optional; leave both empty on deployment so it cannot bypass OAuth expiration. No credential is configured by default. Every request/tool checks the actor is an active verified admin. Keep the endpoint private pending end-to-end testing. Never use provider API keys or account passwords as MCP tokens.

Still required before real ChatGPT use: approved HTTPS domain; ChatGPT account/connector availability and preregistered-client compatibility check; end-to-end connection and actual draft rehearsal. Rate limits exist but production multi-connection and prompt-injection tests remain. Existing AI scheduling settings were not changed by this work; keep `ai_enabled=false` for the budget workflow.

The admin MCP tab now shows configuration presence, endpoint and the current administrator's active OAuth grants, with revoke-all for that actor only. No token/hash is returned. The UI warns separately about any configured development bearer credential, which OAuth revocation cannot invalidate. API tests prove that revoke-all does not remove another admin's grants. Frontend TypeScript checks pass; live browser verification of this new tab is still pending. Worker cleanup removes expired OAuth data and snapshots after 30 days; submitted analysis versions and audit records remain separately stored.

OAuth tests cover consent-before-code, callback rejection, CSRF Origin checks, verifier mismatch, code replay and token revocation. Run `node --test apps/api/src/mcp-oauth.test.js`. No real identity provider or ChatGPT account was used for these tests.

Snapshot tool regression now builds 200 closed candles in PGlite and calls the SDK tool itself. It checks computed metrics, Binance/USDT provenance, source IDs, rejection of stale prices, expired/crossed snapshots and insufficient candle history. An instruction-like news string stays ordinary data and does not publish anything. This does not establish that a real language model resists prompt injection; the separate model rehearsal remains required.

Multi-timeframe update: snapshots now include `timeframes` for 15m, 1h and 4h, each from 200 closed, contiguous, correctly timed candles with its own data timestamp. Missing or stale data in any frame rejects the snapshot. Only 1h metrics contain a conditional plan; other frames are explanatory context. Existing top-level metrics remain the 1h trading-rule output. Regression fixtures now provide 600 candles and assert all three frames and the plan restriction.

Verified locally: SDK client tool listing/calls, HTTP initialization, denial without token and after suspension, unknown sources/numerical overrides rejected, immutable private draft and repeated submission. These checks are not evidence of a live ChatGPT connection.

Login continuation is now implemented: a validated authorization request from a logged-out user sets a ten-minute HttpOnly return cookie and redirects to login. Email/Google login consumes that cookie and returns only to the local OAuth consent path. The consent handler revalidates client/callback/resource/PKCE and admin role; login does not itself grant MCP access. Tests reject external return destinations. The earlier note about requiring login first is superseded; browser rehearsal remains pending.
